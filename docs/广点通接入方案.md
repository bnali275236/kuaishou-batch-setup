# 广点通（腾讯广告）接入方案 · 初稿

> 状态：待评审（2026-11-17）
> 目标：在现有工作台里加入「广点通投放后台」，与快手并列，顶部一键切换。
> 本文所有接口事实均来自腾讯营销开放平台官方文档（v3.0），关键处标注链接，便于你抽查。

---

## 一、目标与范围

| 项 | 内容 |
|---|---|
| 形态 | 同一套网页版工作台，左上角品牌区加「平台切换」，快手 / 广点通两套后台互不干扰 |
| 第一阶段（必须） | 授权 + 账户纳管 + 账户级/广告级报表看板 + 定时同步 + 历史回补 |
| 第二阶段（建议） | 素材库（视频/图片上传）+ 广告/创意列表 |
| 第三阶段（可选） | 批量创编（广告 + 创意两层）+ 盯盘自动规则 |
| 明确不做 | 微信小店/视频号带货深度能力、人群包高级运营、优量汇 ADX 实时竞价 |

## 二、界面：平台切换怎么做

```
┌───────────────────────────┐
│ ● 广告投放工作台  [快手▾] │ ← 品牌区右侧放一个紧凑切换器（Segmented / Dropdown）
├───────────────────────────┤
│ ▸ 盯盘看板                │   ← 菜单随平台切换：快手 6 项 / 广点通 4~6 项
│ ▸ 素材看板                │
│ ▸ 上计划                  │
│ ▸ 应用中心                │
└───────────────────────────┘
```

- 控件：AntD `Segmented`（两段：快手 / 广点通），放在 `app-logo` 右侧；当前平台写进 `localStorage` + 路由前缀。
- 路由：快手沿用 `/dashboard`、`/plan`…；广点通统一前缀 `/gdt/*`（`/gdt/dashboard`、`/gdt/campaigns`、`/gdt/materials`、`/gdt/accounts`）→ 两个平台的页面组件完全隔离，互不影响回归。
- 切平台时：品牌文案、菜单、顶栏徽标（账户数 / 授权状态）全部按平台取数；未配置广点通凭证时，广点通侧显示「接入引导页」（三步：建应用 → 填 client_id/secret → 授权）。
- 一致性：两套页面共用现有的表格、筛选、图表组件，只是数据源换成 `GdtGateway`。

## 三、总体架构（与快手并存，不重构快手）

```
前端  /ks/*  ──┐                    ┌── MapiGateway（现有）───► api.e.kuaishou…
              ├─ api/client.ts ─────┤
      /gdt/* ──┘   (带 platform 头)  └── GdtGateway（新增）────► api.e.qq.com/v3.0
                                         ├─ 限流（按接口令牌桶）
                                         ├─ token 互斥刷新（关键，见 §4.3）
                                         ├─ 错误分类（code/message_cn → 可读错误）
                                         └─ 调用日志（GdtApiCallLog，排障用）
后端  新增 modules/gdt/{auth,account,report,adgroup,creative,asset,task}
       现有 modules/{dashboard,plan,manage,appcenter} 不动
数据库 同库新增 gdt_* 表（不复用快手表，字段口径不同：分 vs 厘、层级不同）
```

原则沿用快手那三条：**密钥不过河、外部调用只走一个网关、本地库是唯一事实源**。

## 四、广点通 API 关键事实（官方文档核对结果）

### 4.1 请求规则
- 正式：`https://api.e.qq.com/v3.0/<resource>/<action>`；沙箱：`https://sandbox-api.e.qq.com`
- **全局参数全部走 query**：`access_token`、`timestamp`（秒级，误差 ≤300 秒，时区 GMT+8）、`nonce`（≤32 字符，全局唯一）
  → 与快手不同（快手放 `Access-Token` 头），网关要单独写
- GET 的非字符串参数要 **JSON 序列化后**再传；POST 用 `application/json`；文件上传用 `multipart/form-data`
- 所有 `get` 接口必须传 `fields` 指定返回字段
- 响应外壳统一：`{ code, message, message_cn, data }`，`code=0` 成功 → 错误提示优先用 `message_cn`
- **金额单位是「分」**（快手是「厘」）→ 落库统一存「分」，展示层 ÷100
- 参数值禁用特殊字符：`< > & ' " / \` 及 Tab/换行/回车 → 计划命名、文案要清洗

### 4.2 授权（两种应用，决定接入路径）

| | 私有应用 | 第三方应用 |
|---|---|---|
| 适用 | 注册 QQ 本身就是广告主/代理商开户 QQ，只管理自己的账户 | 管理他人账户、做代投工具 |
| 审核 | **创建即通过**，可立刻取 token | 2~3 个工作日审核 |
| 拿 token | 应用详情页直接「获取或重置」，10 分钟后生效 | 必须走 OAuth 2.0 |

OAuth 流程（第三方应用）：
1. `https://developers.e.qq.com/oauth/authorize?client_id=…&redirect_uri=…&state=…&scope=ads_management,ads_insights,account_management&account_type=ACCOUNT_TYPE_QQ`
2. 回调带 `authorization_code`（**仅 5 分钟有效**）→ `GET https://api.e.qq.com/oauth/token?grant_type=authorization_code&…`
3. 返回 `access_token`（默认 24h）、`refresh_token`（默认 30 天）

### 4.3 token 生命周期（最大风险点，与快手同构）
- 刷新用**新接口**：`GET https://api.e.qq.com/oauth/refresh_token?client_id=&client_secret=&refresh_token=`
- ⚠️ 新接口是**强制换发**：每次刷新都生成全新的 access + refresh，**旧的立即失效**（老 access 有 10 分钟过渡）。
  官方公告已明确旧方式 `oauth/token?grant_type=refresh_token` 逐步下线，接入直接用新接口。
- 后果与对策（照搬快手的教训）：
  - **只能有一个后端在刷**，刷新必须加分布式/进程内互斥，避免并发刷新互相踢死；
  - token 不落前端、不导出、不多机复制；
  - `refresh_token` 超 30 天不刷新 → 必须重新授权，要有「需要重新授权」告警（照抄快手 `grantNeedReauth` 那套）。

### 4.4 数据层级（3.0 变了，不能按老资料写）
- 3.0 投放层级精简为 **广告(adgroup) → 创意(dynamic_creative)**；老的 `campaign` / `ad` 层级已下线。
- 广告创建需 5 段信息：营销内容（`marketing_goal`/`marketing_sub_goal`/`marketing_target_type`/`marketing_carrier_type`）、版位 `site_set`、定向 `targeting`、出价与预算、广告设置。
- **新增广告唯一性校验**：完全一致的广告只能建一条 → 批量建计划时名称/创意必须带区分标识（对应快手「payload 冻结 + 幂等键」的经验）。
- 组织维度新增：集团 / 主体 / 业务单元（`organization_id`），跨账户管理走业务单元。

### 4.5 报表
- `GET /v3.0/daily_reports/get`：必填 `level`、`date_range`、`group_by`、`fields`，可选 `account_id`、`filtering`、`page`、`page_size`(≤2000)
- `level` 常用：`REPORT_LEVEL_ADVERTISER` / `REPORT_LEVEL_ADGROUP` / `REPORT_LEVEL_DYNAMIC_CREATIVE` / `REPORT_LEVEL_PROJECT` / `REPORT_LEVEL_MATERIAL_VIDEO`
- **可回溯 365 天**（快手只有 7 天，这块反而简单：历史回补只需按账户×日期切片分批拉）
- 单次数据量 `page × page_size ≤ 20000`，超了改用**异步报表任务**（`async_tasks/add` → `get` → 下载 CSV）
- 时效：不按 `site_set` 聚合 → 3 分钟级；按 `site_set` 聚合 → 1 小时级；创意/组件维度 → **T+1**
- 分时用 `hourly_reports/get`

### 4.6 素材（时间点很关键）
- 官方公告：**旧版 v1.1 的 `videos/*`、`images/*` 等素材接口 2026-12-01 下线**，全部迁 `v3.0/videos/add|get`、`v3.0/images/add|get`
- → 我们直接按 v3.0 写，不要用 `tencentads-cli` 里那些 v1.x 示例

### 4.7 配额与沙箱
- 每应用**每接口分钟频次**受限（不同应用等级不同，以应用管理页为准；默认档 1000 次/分钟），超限需停 5 分钟；个别接口另有天频次
- 沙箱：`sandbox-api.e.qq.com`，与正式完全隔离、不产生费用；**数据 7 天清除、30 天不调用回收账号**；沙箱里需先 `advertiser/add` 建子客才能投广告；沙箱暂不支持 OAuth（发永久 token）

## 五、数据模型（新增表，不动快手表）

```prisma
model GdtGrant {                 // 一份凭证（私有应用 token 或一次 OAuth 授权）
  id            String  @id @default(cuid())
  appType       String  // PRIVATE | THIRD
  clientId      String
  clientSecret  String  // 加密存储
  accessToken   String?
  refreshToken  String?
  accessExpiresAt  DateTime?
  refreshExpiresAt DateTime?
  status        String  @default("ACTIVE") // ACTIVE | NEED_REAUTH | DISABLED
  lastError     String?
  nameSyncedAt  DateTime?
  accounts      GdtAccount[]
}

model GdtAccount {
  id          String @id @default(cuid())
  accountId   String @unique       // 广告主 account_id（逻辑主键，字符串存）
  name        String?
  grantId     String
  status      String @default("ACTIVE")
  dailyBudget Int?                // 分
  balance     Int?                // 分
  isAgent     Boolean @default(false)
  syncedAt    DateTime?
}

model GdtDailyStat {              // 账户 / 广告 / 创意三级共用，level 区分
  id       String @id @default(cuid())
  accountId String
  level    String                 // ADVERTISER | ADGROUP | DYNAMIC_CREATIVE
  objectId String?                // adgroup_id / dynamic_creative_id
  date     String                 // YYYY-MM-DD（GMT+8）
  statHour Int    @default(-1)    // -1=日行（与快手表口径一致）
  cost           BigInt @default(0)  // 分
  viewCount      BigInt @default(0)  // 曝光
  validClickCount BigInt @default(0) // 点击
  conversions    BigInt @default(0)
  raw            String?          // 原始 JSON，字段争议时回溯
  @@unique([accountId, level, objectId, date, statHour])
}

model GdtAdgroup { adgroupId String @id, accountId String, name String?, status String?, dailyBudget Int?, bidAmount Int?, marketingGoal String?, siteSet String?, raw String?, updatedAt DateTime }
model GdtCreative { dynamicCreativeId String @id, adgroupId String, accountId String, name String?, auditStatus String?, raw String?, updatedAt DateTime }
model GdtAsset { id String @id, accountId String, kind String /* VIDEO|IMAGE */, mediaId String, name String?, url String?, md5 String?, uploadedAt DateTime }
model GdtApiCallLog { id String @id, path String, accountId String?, code Int, ms Int, at DateTime }   // 排障
model GdtTask / GdtTaskItem   // 批量创编状态机（第三阶段才建，沿用快手 seq/断点续跑/幂等键）
```

设计取舍：
- 不合并到 `ReportDailyStat`（快手表带 `aclick` 等快手专属口径），换来迁移零风险；
- 报表日期用 **GMT+8 自然日**字符串，避免时区错日；
- `BigInt` 存分/次数，前端统一格式化。

## 六、指标映射（直接复用现有看板卡片）

| 看板项 | 广点通字段 | 换算 |
|---|---|---|
| 消耗 | `cost` | ÷100 → 元 |
| 展示/曝光 | `view_count` | 原值 |
| 点击 | `valid_click_count` | 原值 |
| 点击率 | `valid_click_count / view_count` | 百分比 |
| 千展成本 | `cost / view_count × 1000` | ÷100 → 元 |
| 转化数 | `conversions_count`（需实测确认 3.0 字段名） | 原值 |
| 转化成本 | `cost / conversions_count` | ÷100 → 元 |

> ⚠️ 字段名要以**真实调用**为准：3.0 文档示例里出现过 `impression`/`click` 与 `view_count`/`valid_click_count` 两套命名，官方迁移公告也提到指标体系升级。第一步就做一次「小样本真调 + 字段自检」，把对得上的字段固化进 `packages/shared/gdtFields.ts`（快手也踩过「show 不是曝光」的坑）。

## 七、分阶段实施

### P0 平台壳 + 打通鉴权（0.5~1 天）
- 品牌区加切换器、`/gdt/*` 路由、菜单按平台切换、平台偏好持久化
- `GdtGateway`：query 全局参数、nonce 生成、限流、`code/message_cn` 错误分类、调用日志
- 设置页新增「广点通接入」卡片：填 `client_id` / `client_secret`，一键校验（调 `advertiser/get` 自检）
- 账户列表 + 拉一次账户级昨日报表，页面能看到数
- **验收**：切换器可来回切；广点通侧能显示账户与昨日消耗；快手侧无任何回归

### P1 看板 + 定时同步（1.5~2 天）
- 账户级/广告级日报入 `GdtDailyStat`，分时入 `statHour`
- 定时任务：每小时拉前 2 天（对齐 T+1 与延迟），每日 09:20 全量对齐；缺失日写零行占位（照抄快手）
- 看板页复用现有组件：账户多选、日期区间、按天/按时、Top 广告
- 历史回补：365 天按账户×30 天分批，异步任务兜底大账户
- **验收**：随机抽 3 个账户，与投放后台页面数据逐项对齐（消耗/曝光/点击/转化）

### P2 素材与广告/创意只读（1~1.5 天）
- 素材库：视频/图片列表 + 上传（v3.0 `videos/add`、`images/add`）
- 广告/创意列表：状态、预算、出价、版位、审核状态；按名称搜索
- **验收**：上传 1 条视频能出现在素材库并被平台侧可见

### P3 批量创编（3~5 天，风险最高，单独评审）
- 复用快手任务引擎：一层 `adgroup`、二层 `dynamic_creative`，seq=层×10000+行
- 必做：命名唯一化（绕开广告唯一性校验）、payload 冻结、父失败子 SKIP、断点续跑、`errors` 校验
- 默认状态：**先 PAUSED 再人工确认**（广点通审核更严格，别一上来就放量）
- **验收**：3 个账户 × 5 条广告小批量真实建成，回读名称/预算/素材一致

### P4 盯盘（2~3 天，可选）
- 只读告警先上（消耗异常、0 激活、审核驳回、余额不足）
- 再上动作（关停/调预算），全部走 `assertWritable` 白名单与效果回看

## 八、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 应用类型选错（私有 vs 第三方） | 后期无法管理他人账户，返工 | 先确认账户归属再建应用（见 §九） |
| token 强制换发 + 并发刷新 | 互相踢死、全天断数 | 刷新互斥 + 单实例 + 失败告警；沿用快手经验 |
| 3.0 字段名/枚举与文档不一致 | 报表空、指标错 | P0 就做真调自检，字段固化到 shared |
| `page×page_size ≤20000` | 大账户拉不全 | 超限自动切异步报表任务 |
| 旧 v1.1 素材接口 2026-12-01 下线 | 素材功能突然失效 | 只写 v3.0 路径 |
| 计划名含 `& ' " /` 等特殊字符 | 创建报错 | 命名清洗函数统一处理 |
| 分钟频次超限 | 5 分钟全接口不可用 | 网关令牌桶 + 429/超限退避 |
| 沙箱 7 天数据清除 | 联调数据消失 | 联调脚本可重复生成；正式联调用 1 个小额账户 |
| 金额单位分 / 时区 GMT+8 | 数据差 100 倍或错日 | 统一 `fenToYuan()`、日期按 Asia/Shanghai |

## 九、需要你拍板的问题（定了我就开工）

1. **账户归属**：广点通这些账户是你们**自己开户**（自投），还是**代理商代投**？
   → 自投 → 私有应用（当天可用）；代投/多主体 → 必须第三方应用（2~3 工作日审核）。
2. 你手上**有没有开发者账号**（developers.e.qq.com）？有没有已建好的应用 `client_id` / `client_secret`？
3. 广点通账户规模：大概多少个账户、单账户日消耗量级？（决定要不要异步报表）
4. 主要投放形态：竞价 3.0 信息流为主，还是也有微信流量/优量汇？（决定接口范围与版位枚举）
5. 优先级：先做**只读看板**（P0~P1）还是直接冲**批量创编**（P0+P3）？
6. 数据库：与快手**同库不同表**（推荐，切平台不用换服务）还是独立库？
