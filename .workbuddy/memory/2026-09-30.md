## ⚠️ 0.5.1 白屏事故 + 0.5.2 根治（2026-09-30 11:50）—— 重要教训，勿重蹈

**现象**：用户打开 0.5.1 全白屏（浏览器访问同一地址完全正常）。

**根因链**（CDP 远程调试实证）：
1. 服务端 `main.ts` 用 `express.static(..., {maxAge:'1h'})` 托管前端 → **index.html 被 Chromium 磁盘缓存**
2. 升级后 bundle 文件名 hash 变了（index-DcSC_Xws.js → index-0kPc30yp.js），安装包里旧文件已删
3. Electron 仍从缓存拿旧 index.html → 请求已删除的旧 JS → 服务端 SPA 兜底返回 text/html →
   「Failed to load module script: Expected a JavaScript module script but... MIME text/html」→ 白屏
4. 排障弯路：先后怀疑单实例锁/asar 损坏/ELECTRON_RUN_AS_NODE 污染——都不是。**CDP（--remote-debugging-port + Runtime.evaluate 查 root.innerHTML）一击定位**

**0.5.2 三层根治**：
1. `server/main.ts`：index.html 与 SPA 兜底回包加 `Cache-Control: no-store, must-revalidate`；
   assets（hash 文件名）改 `max-age=31536000, immutable` 长缓存
2. `electron/main.js`：`clearCacheOnUpgrade()` —— 版本号变化时 `session.defaultSession.clearCache()`，
   版本记录在 `userData/.last-version`；只在升级时清，正常启动零开销（老缓存已污染，这步是必要兜底）
3. `web/index.html`：加载失败兜底提示（error 捕获 + 6s 后 root 仍空则显示），
   白屏时用户能看到「重新打开/重装」指引而非纯白

**附带发现并修复**：`stage.js` 的 pruneUnreferencedAssets 只按 index.html 判断引用 →
**误删动态 import 的 xlsx chunk**（导出功能会 404）。已改为扫描 index.html + assets 下所有 js/css/json 文本，
任一文件提到该名字就保留。修复后 web 产物 2.5MB→2.9MB（xlsx chunk 429KB 回来了）。

**验证**：0.5.2 安装后 CDP 检查 root 359KB 正常渲染、零 console 错误、截图确认界面完整。

**通用经验**：
- 桌面应用升级后白屏 → 第一反应查「缓存的 index.html vs 新 bundle hash」
- Electron 窗口内排查用 `--remote-debugging-port=9222` + CDP（Runtime.evaluate / Log.enable / Page.captureScreenshot），
  比浏览器侧验证更接近真实（Electron 有自己的缓存分区）
- 本会话 spawn 的子进程随命令结束被沙箱回收，验证 Electron 应用要用 `detached` 且在同一脚本内完成检查；
  或用 `Start-Process explorer.exe "<exe>"` 让 Explorer 代启动（等价双击、环境干净、脱离会话进程树）
- 临时诊断脚本留在 `.tmp-diag/`（cdp-inspect.cjs / cdp-verify-fix.cjs / verify-artifacts.cjs 可复用）
